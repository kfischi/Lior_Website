# מרכז הניהול של כל האתרים

Studio אחד שבו נכנסים פעם אחת ועוברים בין כל האתרים שנבנו מהתבנית. כל אתר הוא "סביבת עבודה" נפרדת, עם התוכן, הצבעים והשדות שלו.

## מי יכול להיכנס
רק מי שהוא חבר בפרויקט ה-Sanity של האתר. החשבון `kfir.biz@gmail.com` (GitHub, kfischi) הוא **Administrator** בפרויקט של ליאור, ולכן רואה אותו כאן. הלקוח לא צריך הרשאה: הוא ממשיך לערוך (אם בכלל) דרך `/studio` באתר שלו, ואפשר לתת לו הרשאה נפרדת בכל עת.

## הרצה מקומית
```bash
npm run hub:dev      # http://localhost:3334
```
בפעם הראשונה: `npx sanity login` (או פשוט להיכנס בדפדפן).

## פרסום (כתובת קבועה על sanity.studio)
```bash
HUB_STUDIO_HOST=my-sites npm run hub:deploy
```
אחרי הפרסום מוסיפים את הכתובת (למשל `https://my-sites.sanity.studio`) ל-CORS של כל פרויקט, עם credentials: sanity.io/manage ← הפרויקט ← API ← CORS origins.

## הוספת אתר חדש
1. יוצרים פרויקט Sanity לאתר (ראו `docs/cms-pilot.md`).
2. מוסיפים שורה ב-`hub/sites.ts`: מזהה, שם, כתובת, `projectId`, `dataset`, צבעים והערות.
3. מפרסמים שוב את ה-hub, ומוסיפים את כתובת ה-hub ל-CORS של הפרויקט החדש.

## מה משותף ומה לא
- **משותף:** מודל התוכן (`src/sanity/schema.ts`, `settings-schema.ts`) והתפריט (`src/sanity/studio-shared.ts`). שינוי שם נעשה פעם אחת ומגיע לכל האתרים, גם ל-`/studio` של כל אתר וגם ל-hub.
- **נפרד:** התוכן עצמו. כל אתר בפרויקט Sanity משלו, כך שלקוח אחד אף פעם לא רואה או מוחק תוכן של לקוח אחר.

## מגבלה נוכחית
המרכז מציג כרגע רק את סביבות העריכה. רשימת האתרים עם סטטוס, אירוח ותאריכי חידוש היא קובץ (`sites.ts`). אם נרצה לוח בקרה עם בדיקות בריאות לכל האתרים, נוסיף לו פרויקט Sanity משלו.
